# v0.1 接口与验收

除健康检查与静态页面外，API 请求需携带 `X-Access-Code`。本版是单项目共享访问码；设备名只作为来源标签。

| 接口 | 用途 |
| --- | --- |
| GET /api/health | 服务健康检查 |
| GET /api/state | 工作空间 ID、最新卡片、全部补充、最近 60 条动态、文件列表、服务端时间 |
| GET /api/connection | 候选局域网 URL |
| POST /api/ai/draft | 把讨论记录整理成可预览的草稿 |
| PUT /api/card | 保存卡片新版本 |
| POST /api/notes | 追加想法 |
| POST /api/files | 在线上传项目文件 |
| GET /api/files/{file_id} | 下载项目原文件 |
| POST /api/resume | 仅将给定 note_ids 标为已查看 |
| GET /api/history/{version} | 获取历史版本 |

所有写请求携带 operation_id（UUID）、device（1—80 字）。同编号同内容重试返回原结果，不重复写入；同编号不同内容返回 409。

卡片字段：project、goal、done、open_questions、next_steps、evidence、version。project 与 goal 必填，project 最多 80 字，其余最多 6000 字。version 是编辑开始时版本，首卡为 0；写事务内原子核对与递增，过期版本返回 409。

补充字段 text，1—6000 字，已有卡片才能补充。恢复只确认点击时已显示的 note_ids，期间新到记录仍保持待查看。

离线补充提交时先写入 IndexedDB，并固定 operation_id。恢复连接后客户端按保存顺序发送，服务端确认后才从本机队列移除。请求携带 `X-Workspace-Id`，服务端拒绝属于其他工作空间的补充；旧客户端可以继续使用现有接口。

上传使用 `application/octet-stream`，查询参数为 `name`、`device`、`operation_id`。单文件上限 20 MB，同一操作编号重试不会重复保存。项目状态只列文件信息，下载走带访问码的独立接口。文件作为附件下载，原始内容与元数据保存在 SQLite。

## AI 草稿联调约定

`POST /api/ai/draft` 沿用 `X-Access-Code`。请求体为 `{"text":"讨论原文"}`，输入长度 1–6000 字。返回体形如：

```json
{
  "mode": "demo",
  "draft": {
    "goal": "完善登录流程",
    "done": "完成登录页",
    "open_questions": "确认错误提示文案",
    "next_steps": "验证密码错误时的提示",
    "evidence": "讨论记录中提到的依据"
  }
}
```

每个字段为字符串，无依据时可返回空字符串。`ai_draft.py` 的 `generate_draft(text)` 是队长接入模型的位置。目前 `mode` 为 `demo`，使用本地规则提取带标签的行。接入后返回 `mode: "model"`，把模型密钥放在后端环境变量。重要结论需引用输入中可核对的原文。模型请求建议限制在 30 秒内，超时抛出 `TimeoutError`，服务不可用时抛出 `DraftUnavailableError`，后端分别返回 504 和 502。

生成接口只返回预览。用户选择填入的字段，在编辑框核对后继续使用 `PUT /api/card` 保存新版本。这样手机同步和并发冲突仍由原有接口处理。

## 并发编辑验收

旧版本保存仍返回 409。客户端根据打开编辑时的版本、当前草稿和最新版本合并各字段。两端改到同一字段且内容不同，需要选择保留哪一版。合并后由用户查看草稿并重新保存。

字段合并和离线队列共 4 项前端测试通过，7 项后端测试及生产构建通过。真实手机与电脑的冲突弹窗操作待验收，步骤见 README 的「五分钟测试」。
