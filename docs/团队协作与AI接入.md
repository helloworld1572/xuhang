# 续航 v0.2：团队协作与 AI 接入准备

## 当前完成范围

团队工作台是新的默认入口：成员跨设备登录 → 创建或加入团队 → 项目与阶段计划 → 分配任务 → 更新状态及完成打钩 → 所有成员查看真实进度。成员、项目、任务、附件和操作历史都持久保存。

技术栈保持 Vue 3 / TypeScript、FastAPI、SQLite，电脑与手机访问同一个后端。轮询间隔为 5 秒，切回页面时也刷新。没有新增外部模型、数据库或账号服务。

## 两个人如何使用

1. 停止旧服务，运行 `启动续航.cmd`。电脑打开 `http://127.0.0.1:8765`；手机使用启动窗口中电脑 Wi-Fi 网卡的地址。
2. A 在“第一次使用”填写名字，选择“使用电脑服务访问码”，输入启动窗口显示的访问码。注册后展开“在另一台设备登录”，保存自己的个人登录密钥。
3. A 创建团队和项目。在团队成员区点击“生成一次性邀请码”，将邀请码提供给 B。
4. B 在自己的设备打开同一个服务，选择“使用队友给的邀请码”，填写名字和邀请码注册。已有身份的 B 可以登录后在“加入其他团队”输入邀请码。
5. 两人点击团队名、项目名。A 在“阶段计划”添加阶段，在“团队任务”创建任务，填写完成标准、阶段、负责人和可选截止日期。
6. B 打开“我的任务”，更新为进行中或受阻，填写结果说明，也可在详情中发布评论。完成后勾选任务。
7. A 在“项目概览”看到任务完成率和操作动态。取消勾选会把任务重新打开为进行中，原完成事件继续保留。
8. 同一个人在其他设备登录时，使用自己的个人登录密钥；不要再次注册成另一个成员。设备必须访问同一台服务。

个人登录密钥是浏览器随机生成的 256 位凭据，服务端只保存 SHA-256 摘要。昵称不是登录凭据。同一地址的同一浏览器默认共享登录身份；双成员测试应使用不同浏览器、无痕会话或不同设备。当前不提供密码找回、密钥轮换和成员移除；请保存个人密钥。退出会清除当前浏览器保存的登录密钥，不删除成员和任务。

团队邀请码同样为随机凭据，一次性使用，7天过期；管理员可以撤销。队友只需邀请码，不需要电脑服务访问码。服务访问码还能访问原工作空间，应仅由原资料管理者持有。

## 权限与进度含义

- 团队创建者为管理员。只有管理员可以发放和撤销邀请。
- 团队成员可以创建项目、任务、评论、附件和接续卡。
- 项目负责人及管理员可以编辑项目和阶段、调整任务负责人、更新团队任务。
- 普通任务负责人可以更新自己任务的状态、进度/结果、受阻原因和关联附件；不能修改他人的分配或自行改写完成标准。
- 普通成员新建任务可以先不分配，或分配给自己。给其他人分配任务由项目负责人或管理员操作。
- 只有指定接手人可以确认交接；接手不会自动完成任务。
- 非成员读取、修改、下载、读取 AI 上下文均由服务端拒绝。任务的阶段、附件和评论必须属于同一项目。
- 任务完成率是已完成任务数除以任务总数，不代表工作量比例。空项目显示“尚未安排任务”。逾期按北京时间日期计算，已完成任务不计为逾期。
- 项目“已结束”是负责人设置的计划状态，不自动勾选任务；成员的任务数量不是能力评分。

## 旧数据与迁移

新版本在现有 `data/xuhang.sqlite3` 中新增 `collab_*` 表及 `collab_schema` 版本记录。没有删除、重命名、清空或自动归属旧表，也没有将旧资料开放给新团队。重复启动会检查已有表，不重复创建记录。

原接续卡、离线文字补传、历史版本、文件和交接继续从顶部“打开原工作空间”使用原访问码进入。新团队成员身份与旧工作空间的浏览器交接身份独立。

项目负责人或管理员可以在“资料与接续 → 导入旧工作空间的一张接续卡”，输入原访问码和已核对的版本号，确认复制到当前项目。导入卡片会对当前团队可见，原卡片继续保留。旧附件如需共享，应先从原工作空间下载，再上传到明确的团队项目，不自动搬移全部文件和讨论。

备份：先停止服务，再复制整个 `data` 目录。升级前已有的备份仍适用于旧版；新团队数据只有新版能够读取。不建议用旧版对新增团队数据进行操作。

## 新接口

除注册外，下列接口都需要请求头 `X-Member-Key`。统一前缀 `/api/collab`。服务端根据成员身份判断权限，不接受客户端提交的操作者名称作为身份。

| 方法与路径 | 用途 |
| --- | --- |
| POST /register | 名字、个人随机 key、服务访问码或邀请，注册成员；同 key 重试返回同一成员 |
| GET /me | 当前成员及加入的团队 |
| POST /teams | 创建团队及管理员关系 |
| GET /teams/{tid} | 团队成员、项目、管理员可见的邀请状态 |
| POST /teams/{tid}/invites | 创建7天有效的一次性邀请码，客户端生成随机 code |
| POST /teams/{tid}/invites/{iid}/revoke | 撤销邀请 |
| POST /join | 已有成员凭邀请加入团队 |
| POST /teams/{tid}/projects | 创建项目 |
| GET /projects/{pid} | 项目状态、记录、文件信息、进度、最近60条动态 |
| PUT /projects/{pid} | 按 version 更新项目计划 |
| POST /projects/{pid}/records/{kind} | 创建 stage、task、card、note 或 handoff |
| PUT /projects/{pid}/records/{eid} | 按 version 更新阶段、任务或接续卡 |
| GET /projects/{pid}/records/{eid}/history | 单条记录的操作历史，每页50条，以 before 向前翻页 |
| POST /projects/{pid}/handoffs/{eid}/accept | 指定成员确认接手，保留发布时卡片快照 |
| POST /projects/{pid}/import-card | 双重权限校验后复制指定旧卡片版本 |
| POST /projects/{pid}/files | 原始文件上传，query 为 name 和 operation_id，最多20 MB |
| GET /projects/{pid}/files/{fid} | 当前项目内授权下载原文件 |
| GET /projects/{pid}/context | AI 可用的有限项目事实与来源 |
| GET /ai/suggestion-schema | 后续 AI 建议 JSON Schema |

写请求携带 UUID `operation_id`。成员、请求路径及内容共同确定一次操作；同一成员同编号同内容重试返回原结果，内容不同返回409。操作、版本变化和动态在同一次 SQLite 写事务中提交。不同成员可独立使用相同操作编号。

创建或更新记录的请求示例：

```json
{
  "operation_id": "具有UUID格式的唯一操作编号",
  "version": 1,
  "data": {
    "title": "验证错误密码提示",
    "description": "使用三组错误密码进行测试",
    "criteria": "每次均显示明确错误，且不会登录成功",
    "stage_id": null,
    "assignee_id": 2,
    "due_date": "2026-11-22",
    "status": "doing",
    "result": "已经完成两组测试",
    "blocked_reason": "",
    "file_ids": []
  }
}
```

状态值为 `todo / doing / blocked / done`。任务完成者、完成时间由后端产生。旧 version 修改返回409，不覆盖新数据。页面保留旧草稿，用户可复制所需内容后载入最新版重新编辑。本轮没有自动合并团队任务字段。

## 后续如何接 AI

`GET /projects/{pid}/context` 根据当前成员权限读取项目。返回项目 revision、真实任务状态计数、阶段与任务等记录、成员、近期变更及附件元数据，不返回密钥和附件正文。

记录部分最多100条且累计不超过50000字符；另外最多100位成员、20份附件元数据和20条近期变化。存在截断时返回 `truncated: true` 与范围说明。阶段和任务优先，AI 不能将截断结果当作全量项目证据。

每条来源形如 `record:12:v3`，包含实际读取的记录内容、作者、时间和版本。项目 revision 在内容变化时递增；团队成员变化不改变项目 revision，因此未来应用建议时仍必须重新校验成员资格。

`AISuggestion` 契约支持进度总结、建议新任务、建议分配负责人、建议调整计划，并携带项目 ID、依据 revision、来源引用、解释和建议内容；状态只允许 `pending_confirmation`。

本轮提供事实读取和建议格式，没有模型调用、AI 建议存储、生成或应用接口。下一轮接入时应保存本次实际提供给模型的来源快照、验证来源 ID，让用户编辑确认；应用时再次检查项目 revision、相关记录 version 与当前权限，并通过本模块业务校验写入。禁止让模型绕过权限直接执行数据库写入。

## 验证命令与边界

2026-11-15 本轮验证结果：后端22项测试通过，前端6项测试通过，TypeScript检查及生产构建通过。无头Chrome双会话完整流程通过，1440像素桌面与390像素手机尺寸均未发现横向溢出，未捕获页面脚本异常。测试过程中发现并修复了旧页面样式影响新侧栏、任务筛选保留了“只看我的”、冲突处理后旧提示未清理等问题。

启动新版前使用 SQLite 在线备份生成 `data/backups/before-team-20261115-225620.sqlite3`。升级后逐表核对8张旧业务表，内容与备份一致；新增协作结构版本为1。真机、校园网及跨网络访问仍需用新版另行验收。

```powershell
.venv\Scripts\python.exe -X utf8 -m pytest -q
npm test
npm run build
```

```powershell
npm install --prefix ..\tmp\xuhang-browser-qa --no-save playwright-core

```

截图保存在工作区的 `tmp/xuhang-browser-qa/screenshots/`。浏览器脚本覆盖两名成员、邀请、任务分配、完成同步、跨设备身份、版本冲突、断网保留输入和手机尺寸布局。浏览器手机尺寸模拟不等于真实安卓手机验收。

当前仍是可互访局域网 HTTP 原型，电脑须开机运行。同一 Wi-Fi 可能存在设备隔离，可改用可信热点。不同网络访问需要稳定的 HTTPS 地址、受控转发或部署方案；本次未启用公网入口，也未恢复旧备份中的安卓与远程隧道代码。旧APK不等于已经验证支持新版协作流程。

团队任务、评论、文件和交接当前需要在线保存；原工作空间的 IndexedDB 离线补传保留。个人密钥按浏览器网址保存，换地址时可用原密钥重新登录同一服务。团队数据当前按整个项目读取，适合小型学生项目；大规模任务列表、账号恢复与成员管理需要后续扩展。
