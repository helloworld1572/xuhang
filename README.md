# 续航 · 同一 Wi-Fi 工作接续 v0.1

电脑保存接续卡 → 手机查看并补充 → 电脑查看变化、恢复工作。

技术栈：Vue 3 + TypeScript + Vite；Python + FastAPI；SQLite。构建后的网页由同一个 Python 服务提供，手机只需访问一个地址。

## 这台电脑怎么运行

依赖已安装，网页已构建。

1. 双击 **启动续航.cmd**，保留运行窗口。
2. 电脑浏览器打开 **http://127.0.0.1:8765**。
3. 启动窗口显示项目访问码、手机候选地址。访问码也在 `data/access-code.txt`，重启不会改变。
4. 手机接入能访问电脑的网络，在浏览器打开启动窗口中 **WLAN / Wi-Fi 网卡对应地址**。手机不能用 localhost 或 127.0.0.1 访问电脑。
5. 两端分别填写“我的电脑”“我的手机”，输入同一访问码。

校园网已验证电脑连 `web.wlan.bjtu`、手机连 `phone.wlan.bjtu` 的组合。换网络后地址可能变化，以启动窗口或电脑 `ipconfig` 的 WLAN IPv4 地址为准。

后台服务已运行时可直接打开网页。再次启动会提示已在运行。双击 **停止续航.cmd** 停止本项目服务；前台运行也可按 Ctrl+C。停止服务不删除数据。

## 用两台设备测试团队交接

1. 更新后先停止旧服务，再双击 **启动续航.cmd**。电脑 A 用本机网址，设备 B 用启动窗口里的电脑 Wi-Fi 地址。两端用同一个项目访问码登录，尽量用可信热点或可互访的 Wi-Fi。
2. 两端在「工作接续」页找到「团队交接」，分别用不同的名称加入，例如「小林」和「小周」。电脑 A 保存一张接续卡，点「刷新进度」，从「指定接手人」选择小周并点「发布交接」。两端应显示「小林 → 小周」和「待接手」。
3. 设备 B 在线时可以上传一张截图。也可以让手机暂时断开连接，在已打开的网页填写一条补充并离线保存，再恢复连接，确认电脑 A 收到这条补充和截图。
4. 设备 B 点「确认接手」。电脑 A 等约 5 秒或点「刷新进度」，应看到「已接手」。两端的「接续记录」应显示发布和接手两条事件。可重启服务确认状态仍保留。
5. 可选验证。发布后、接手前，用电脑 A 再编辑一次接续卡。设备 B 能在「团队交接」展开发布时的旧版本，确认接手仍针对那一版。

团队交接首版每个工作空间同时处理一项待接手交接。加入后的身份绑定当前浏览器和网址，同一浏览器的两个普通标签页共用身份。测试期间请让接手人使用加入时的浏览器和原网址，保留站点数据。项目仍用共享访问码，补充和文件沿用同一工作空间。

## 五分钟测试

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 电脑保存 | “保存第一张接续卡”或“编辑并保存现场”，填写并保存 | 保存成功提示、时间、递增版本号 |
| 手机查看 | 手机登录，必要时“刷新进度” | 与电脑相同的卡片和版本 |
| 手机补充 | 输入“来自真实手机：测试密码错误提示”，提交 | 输入框清空、成功提示、新的待查看记录 |
| 双端传文件 | 在「工作接续」页底部的「项目文件」选一个小文件并发送，在另一端下载。也可以换方向再传一次 | 另一端约 5 秒内看到文件名和大小，下载的文件内容与原文件一致 |
| 电脑恢复 | 等待约 5 秒或刷新，点“我已查看，继续工作” | 待查看数量减少；接续记录仍保留补充 |
| 验证持久化 | 刷新网页、停止并重新启动服务 | 原有卡片、补充和恢复记录仍在 |

“继续工作”表示已查看当前补充，不表示任务完成，不自动改写接续卡。需要更新下一步时手动编辑确认。

联调示例已明确标注，可直接改成自己的真实项目。第二浏览器会话和移动尺寸模拟不能替代真实手机测试。

并发修改可用两台设备打开同一版本验证。先在电脑改「已完成」并保存，再在手机旧草稿里改「下一步」并保存。冲突时点「合并到草稿」，确认两处改动都在后再保存。若两端改了同一字段且内容不同，先选择要保留的版本，再合并并保存。建议用演示卡或独立测试数据操作。

草稿联调可以在接续卡编辑窗口展开「从讨论记录生成草稿」，点「使用演示材料」后生成，勾选字段并填入编辑框，再核对并保存。当前草稿由本地规则整理。队长接真实模型时按「AI 草稿联调约定」实现同一个接口。

## 手机断网保存与自动补传

1. 手机上先刷新到新版、登录并打开已有接续卡。让手机和电脑暂时断开连接。用手机热点时，可在电脑停止续航服务来模拟连接中断，热点与 IP 保持不变。
2. 保持手机页面打开，在「随手补充」填写两条不同内容，分别点「离线保存」或「提交补充」。应出现「已存本机 · 待同步 2 条」，下方能看到原文。
3. 恢复 Wi-Fi，或重新启动电脑服务。手机保持页面打开或切回原页面，无需再点提交。页面会自动重试，成功后待同步列表清空。电脑每 5 秒刷新一次，也可点击「刷新进度」。
4. 电脑确认每条内容只出现一次。手机补传成功前关闭页面，等网络恢复后在**同一个浏览器、同一个网址**重新打开并登录，待同步记录也会自动恢复并发送。

已提交的待同步补充存在 IndexedDB，清除浏览器网站数据会删除本地队列。当前 HTTP 局域网页面需要联网才能首次加载，断网前请先打开。浏览器关闭或长时间在后台时，请在联网后切回页面，让自动补传继续。网址的 IP 或端口改变后，浏览器会把它当成另一个站点，原队列留在旧网址。

## 手机打不开时

1. 电脑打开 `http://127.0.0.1:8765/api/health`，应看到 `ok: true`。
2. 手机明确输入 `http://电脑WiFi地址:8765/api/health`，不要改为 https。
3. 核对两端 Wi-Fi 名称和 IP；手机暂时关闭移动数据、VPN或代理。
4. 若出现 Python 防火墙提示，在你信任的当前网络上允许访问，不要整体关闭防火墙。
5. 校园网/访客网可能禁止设备互访。同一 Wi-Fi 并不保证能互访；可以用手机开启热点，让电脑连接此热点，再查电脑新 IPv4 地址，手机访问新地址。
6. 电脑休眠、断网或服务退出后无法同步。重新联网并恢复服务后网页会自动重试查询。

本版是可信局域网 HTTP 原型；访问码提供基本隔离，传输尚未加密，不用于公网或敏感材料。

## 队友首次安装

建议 Python 3.12、Node.js 22.12+ 或 24。命令在本项目目录运行。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
.venv\Scripts\python.exe -X utf8 start.py
```

也可用 uv：

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
npm ci
npm run build
.venv\Scripts\python.exe -X utf8 start.py
```

本机使用 uv 创建的环境未默认安装 pip，增装依赖请用 uv。双击脚本固定使用项目自己的 Python，不使用系统的 Python 3.15。

修改前端后运行 `npm run build` 并刷新网页；修改 Python 后重启服务。开发模式可用 `npm run dev`，手机演示使用 8765 端口。

## 从哪里读代码

| 文件 | 作用 |
| --- | --- |
| `src/App.vue` | 页面、表单、请求、定时刷新、版本冲突提示 |
| `src/style.css` | 手机和电脑自适应布局 |
| `src/noteQueue.ts` | IndexedDB 待同步补充队列 |
| `server.py` | 接口、数据库与版本事务 |
| `network.py` | 检测候选局域网地址 |
| `start.py` | 启动服务、显示地址和访问码 |
| `tests/test_handoff.py` | 双端流程、持久化、冲突、去重、权限与并发测试 |

一次保存的路径：`App.vue` 的 `saveCard()` → `PUT /api/card` → `server.py` 的 `save_card()` → SQLite 的 cards 表 → 重新查询 `/api/state` 更新页面。

手机补充走 `POST /api/notes`；电脑每 5 秒查询 `/api/state`。两端共享后端数据库，无需直接复制文件。

## 数据与测试

真实数据在 `data/xuhang.sqlite3`；访问码在 `data/access-code.txt`。不要把 data、.venv、日志和 node_modules 提交到 Git。备份时先停止服务，再复制整个 data 目录。

```powershell
.venv\Scripts\python.exe -X utf8 -m pytest -q
npm test
npm run build
```

测试使用独立临时数据库，不覆盖真实数据。当前 Starlette 测试工具会给出一条 httpx 弃用提醒，测试兼容通过。

## 本版范围

- 一个项目、一个共享访问码；设备名是显示标签，不是独立用户账号。
- 文字接续卡、补充、恢复与历史；每 5 秒查询，切回页面也查询。
- 服务端保存历史版本与操作编号，旧版本不能直接覆盖新版本，失败重试不重复创建记录。
- 文字补充支持本机离线保存、联网自动补传。接续卡编辑仍需连接电脑服务。
- 项目文件支持在线上传和下载，单个文件最多 20 MB，文件保存在运行服务的电脑上。上传失败时可在当前页面重试。项目内有访问码的设备都可以下载。
- AI 草稿已提供演示接口，真实模型待接入。语音、多项目、独立权限、公网访问和双节点调度另行安排。
